# Vocabulary Expansion to 5,000 Cards — Implementation Plan

> **For agentic workers:** this campaign spans dozens of sessions and will outlive
> many context windows. **Re-measure before planning any phase** — see
> "Measurement commands" below. Do not trust counts quoted in conversation.

**Goal:** raise the dictionary from 2,364 format-2 cards to ≥5,000.

**Approved bar (2026-10-03):** every new card meets **full format 2**. No lighter
tier, no new `CARD_FORMAT`. If volume ever forces a lighter class, the correct
lever is a new **`depth`** value, not a format bump — `format` in this project
ratchets upward in richness (format 1 cards are flagged "needs an upgrade"),
while `depth` is already the semantic axis.

## Baseline, measured 2026-10-03

| quantity | value |
|---|---|
| card files on disk | 2,364 |
| `ranked.json` lemmas | 2,000 — 1,855 carded, 145 excluded, **0 pending** |

Exclusion reasons already in use across the 145: `proper-noun` 65, `no-corpus` 23,

### Supply is sufficient; the ceiling is one constant

- `pl_50k.txt` — 50,000 frequency-ranked **forms** (hermitdave 2018, film subtitles)
- `PoliMorf-0.6.7` — 3,800,454 distinct forms
- `pl-extract.jsonl` — 502,919 Wiktionary entries
- `scripts/dictionary/cli/rank.ts:15-16` — `FORM_LIMIT = 20000`, `LEMMA_LIMIT = 2000`

A probe at `FORM_LIMIT=50000` yielded **≥6,000 lemmas**. Beyond rank 2,000 there
are 4,000 lemmas, of which **410 are capitalised names** (~10%) and 41 are ≤2
characters. POS spread beyond 2,000: noun 2,462 · verb 879 · adj 454 · adv 126 ·
part 31 · interj 22 · num 11 · prep 10 · conj 5.

Band quality is good learner vocabulary — `narzeczony`, `umiejętność`, `diament`,
`narzekać`, `zastępca`, `garaż`, `nastolatek`, `wątroba`, `paszport`, `ustawa`,
`przyjazd`, `studentka`, `przemysł`, `tętno`, `krajowy`, `łapówka`. Junk is
confined to personal names (`Brandon`, `Sandra`, `Watson`), place names
(`Seattle`, `Australia`), and acronyms (`usa`, `cia`).

### Corrected cost model

An earlier estimate of ~90,000 examples was **wrong by ~4×**: it used a median of
10 forms/card taken from existing cards, which skew noun-heavy. Verbs carry a
median of **68 forms**.

| | cards | forms | examples (3/form + 5 senses) |
|---|---|---|---|
| Phase 0 | 69 | 2,795 | ~8,730 |
| Phases 1–2 | ~2,567 | ~58,000 | ~187,000 |
| **total** | **~2,636** | **~61,000** | **~196,000** |

There is effectively **no bilingual corpus**: `pol-rus_links.tsv` has 228 pairs
total, and draft candidates routinely come back with `ru: null`. Assume every
example is authored.

**Correction (2026-10-03, later):** the figures above are inflated by roughly a
fifth. A draft's `allForms` includes negated variants (`nienarzekajaca`,
`niesiegania`), but `affirmativeForms()` in `scripts/dictionary/lib/draft.ts`
strips any `nie`-form whose remainder is also present, and the validator's
"examples for every form" check runs on that filtered set. So `narzekac` needs
52 forms, not 66 — and `przywiezc` confirms it retroactively: 69 `allForms`,
52 covered on the committed card. **Always size a card from
`affirmativeForms(allForms)`, never from `len(allForms)`.**

## Phases

### Phase 0 — the 69 already-registered pending cards

No pipeline change, no exclusion curation, no decisions. Drafts for all 69 were
generated 2026-10-03 (`pnpm dict:draft --ids …`, report `data/batches/pilot.md`).

Composition: 33 verbs (2,495 forms), 16 nouns (147), 8 adj (131), 6 adv (16),
5 interj (5), 1 part (1).

**Order of work:** cheapest first to bank progress — interjections and particle
(6 cards, 6 forms), then adverbs (6/16), then nouns (16/147), then adjectives
(8/131), then verbs (33/2,495). The five greeting interjections
(`do-widzenia`, `dobry-wieczor`, `dzien-dobry`, `jak-sie-masz`, `milo-mi`) also
clear five long-standing `pnpm validate` warnings about lesson words with no
dictionary card.

### Phase 1 — raise the ceiling

1. `rank.ts`: `FORM_LIMIT = 20000 → 50000`, `LEMMA_LIMIT = 2000 → 5400`
   (5,400 raw nets ~5,000 usable after ~10% name attrition).
2. `pnpm dict:rank` — **overwrites `data/ranked.json`**. Commit the current file
   first; it is generated, but a bad re-rank is easier to revert than to redo.
3. ~~Curate exclusions for the new band~~ — **see "Exclusion curation is NOT a
   prerequisite" below; this is not a Phase 2 blocker and must not be done by
   heuristic.** Original text: curate exclusions in `data/overrides.yml` (`exclude` +
   `excludeNotes`). Use only the closed vocabulary in
   `scripts/dictionary/lib/rank.ts` → `EXCLUSION_REASONS`:
   `form-of`, `variant-of`, `foreign`, `proper-noun`, `no-corpus`, `not-a-lemma`.
   `form-of` and `variant-of` **require** a `see:` pointing at the owning card.
   Expect ~410 `proper-noun` additions. Keep geographic terms that function as
   vocabulary; exclude personal names.
4. `pnpm dict:status` to stamp statuses back into both registries.

### Phase 2 — author ranks 2,001–5,400 in frequency order

Batches of 200 (`dict:draft`'s native `BATCH_SIZE`): `pnpm dict:draft --batch N`,
author, `pnpm dict:build`, `pnpm validate`, `pnpm dict:status`, commit.

Within a batch, work cheapest-POS-first as in Phase 0 so each session ends with
whole cards committed rather than a half-finished verb.

## Per-card recipe

Template: `content/dictionary/trakt.yml`. Field order matters for review diffs.

```
# review            ← keep until the owner has checked the Polish
id, format: 2, lemma, rank, pos
pron: { cyr: "…" }  ← transcription rules in CLAUDE.md
senses:             ← ≥1 sense; ≥5 sense examples TOTAL across senses
notes:              ← kinds: usage | government | false-friend
collocations:
family:             ← { pl, ru, relation, id? }; drafts supply `related`
etymology:          ← required by format 2
memory:             ← required by format 2
idioms:             ← ≥1 required by format 2
formExamples:       ← 3 per form, or a formExamplesSkip entry
formExamplesSkip:   ← { form, reason } — reason must state GRAMMAR, never corpus
```

### Hard rules carried over from the skip-backlog campaign

These were settled over many sessions; re-deriving them wastes a session.

- **Never skip a form because the corpus is empty.** Author the example. A skip
  reason must name a grammatical obstacle.
- **Government decides passives.** No accusative object → no passive participle.
  A dative participant cannot be promoted. Masculine-personal passive needs a
  *person* object.
- **Aspect decides participles.** `-wszy` only from perfectives; present
  participles only from imperfectives. Read the card's aspect note per card — it
  cannot be regex-parsed.
- **The `by` clitic adds no syllable**, so it does not reopen a closed syllable:
  `przywiózłby`, not `przywiozłby`.
- **Reflexive-only verbs** need `się` in every example (use the guard's
  `need_sie`).
- **Classifying adjectives do not grade** (`stały`, `tajny`, `ranny`); gradable
  ones do (`pusty`, `świeży`, `szalony` — dictionaries list `szaleńszy`).
- **Pre-1936 `-yj`/`-ij` genitive plurals** stay refused as archaic: `teoryj`,
  `racyj`, `technologij`.
- A homograph does not take a form away from its own card: `przyszły` is the
  adjective's nominative as well as `przyjść`'s past.

## Pipeline order

`dict:draft` → author the `.yml` → `dict:build` → `pnpm validate` →
`dict:status` → commit. `content/forms/*.json` is **generated** by `dict:build`;
never hand-edit it. `data/ranked.json` is generated by `dict:rank`; anything
hand-curated belongs in `data/words.json` or `data/overrides.yml`.

## Phase 1 aftermath: two things this plan did not anticipate

Both cost real time on 2026-10-03 and will recur on any future re-rank.

### 1. The registry is ranked.json OVERLAID BY words.json

`scripts/validate-content.ts:17` builds the cross-check registry as
`[...readRegistry(DATA.ranked), ...readRegistry(DATA.words)]`, and
`validate-dictionary.ts:110` turns that array into a `Map` keyed by `id`. Later
entries win, so **for any id present in both files, `data/words.json` is
authoritative.** A card's `rank:` must therefore be stamped from that
precedence, never from `ranked.json` alone — doing the latter leaves every
words.json-registered card failing validation with the two values transposed,
which reads confusingly like a stale cache.

### 2. Raising LEMMA_LIMIT collides with words.json's numbering

CLAUDE.md gives hand-added words "ranks from 2001 up", which held only while
the generated set stopped at 2000. With `LEMMA_LIMIT = 5400` the two numbering
spaces overlap and `pnpm validate` reports `duplicate rank N` for every
collision (154 cards across 77 ranks when first hit).

The invariant restored on 2026-10-03, and the one to preserve: **shared ids
agree with `ranked.json`; words.json-only entries live above the generated
ceiling.** They now occupy 5401–5777 (377 entries). If `LEMMA_LIMIT` rises
again, re-park them above the new ceiling in the same pass.

### Order of operations for a re-rank

1. Commit the clean tree first — `dict:rank` overwrites `data/ranked.json`.
2. Edit `FORM_LIMIT` / `LEMMA_LIMIT`, run `pnpm dict:rank`.
3. Make shared words.json ids agree with the new ranked.json; re-park
   words.json-only ids above the ceiling.
4. Re-stamp every card's `rank:` from the precedence map.
5. `pnpm dict:build` → `pnpm validate` → `pnpm dict:status` → commit.

Skipping step 3 or 4 leaves the tree red in a way whose error text points at
the wrong cause.

## Exclusion curation is NOT a prerequisite for Phase 2

Settled 2026-10-03 after a wrong turn. Phase 1 listed exclusion curation as
step 3, implying Phase 2 waits on it. It does not, and attempting it by rule
produces wrong answers.

### Why it is off the critical path

Exclusions create no cards; they only mark a lemma as not needing one. After
the re-rank: 3,228 pending lemmas, of which 2,876 are clean and 352 are
junk-flagged — against roughly 2,570 cards still needed for the 5,000 target.
There is ample good vocabulary without touching the junk. Author in rank
order and exclude opportunistically, using the evidence each draft supplies,
which is also the only way to meet the house standard.

### Why the obvious heuristic fails

PoliMorf has a fourth column carrying `pospolita` (common noun) or empty.
Empty looks like a proper-noun marker — `Josh` is empty with `m1` gender and
depreciative plurals, `GUS` is `pospolita` and fully declining. It is not a
usable discriminator. Tested against the owner's own 173 exclusions:
**0 classify as "proper"**, while 78 come back `pospolita`, among them `bill`,
`bob`, `mary`, `frank`, `jack`, `daniel`, `don`, `donna`, `nick`, `sherlock`
and `abba`. The rule would have kept Mary and Bob while excluding `Rosjanin`,
`Brytyjczyk`, `Hiszpania` and `Moskwa`. The flag apparently records only that
*some* common-noun entry exists for the string.

The house standard, visible in every existing entry, is prose evidence from
real candidates ("все кандидаты — личное имя (Peter kocha Jane…)") plus an
`excludeNotes` reason from the closed vocabulary. That needs per-lemma draft
data, so curate exclusions **from drafts, in the batch where you meet them.**

### Carve-outs any exclusion pass must respect

Checked before writing a single exclusion, and each one is a real trap:

- **Already carded** — `Rosja` has a written card. Excluding it contradicts the card.
- **In `data/words.json`** — `Rosja`, `Hall`. These are the owner's own additions.
- **Already in `overrides.yml`** — 22 of the flagged entries, including `Josh`,
  `Jeff`, `Abba`, `Angeles`, `KM`, `Niemiec`, `Hall`. Re-adding duplicates keys.
- **Capitalised ≠ name.** Polish capitalises nationality nouns, so `Rosjanin`,
  `Amerykanin`, `Brytyjczyk`, `Indianin` are ordinary vocabulary; and the plan
  already says to keep geographic terms that function as vocabulary — `Rzym`,
  `Japonia`, `Włochy`, `Egipt`, `Korea`.
- **`e-mail` is standard Polish** despite the hyphen and the Latin letters.
- **`GUS` and `ONZ` decline** (`GUS-u`, `GUS-em`, `GUS-ach`) and are lexicalised,
  so the all-caps class is not uniformly junk either.

### Two practical notes

- `dict:draft --batch N` selects a fixed rank **window** (`(n-1)*200 < rank <= n*200`),
  not "the next 200 pending". A curated id list needs `--ids a,b,c`, which throws
  if any id is absent from the registries.
- A junk filter of "capitalised, or <=2 chars, or non-Polish letters" leaks:
  `china` (Polish is `Chiny`) and `amerykan` (a genitive-plural fragment) pass it.
  Do not trust it as a gate; use it only to order work.
